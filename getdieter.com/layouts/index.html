Architecture

A daemon owns the code. A gateway only relays.

Clients try a direct TLS route first, then fall back to the gateway—the same DieterService API either way.

  • {{ partial "icon" "check" }}Daemon — projects, conversations, terminals, and local agents.
  • {{ partial "icon" "check" }}Gateway — one GitHub identity, relaying to every enrolled daemon.
  • {{ partial "icon" "check" }}Clients — macOS & Android, routing each action to the owning machine.
  • {{ partial "icon" "check" }}Never stored — no code, transcripts, or credentials leave home.

Security

Your code stays on your machines.

Agents run locally. The gateway relays between them—it never stores code, transcripts, or keys.

{{ partial "icon" "key" }}

Proven every connection

Each daemon proves its Ed25519 key; every relayed request is signed and bounded.

{{ partial "icon" "lock" }}

Loopback by default

The data plane stays on 127.0.0.1. Remote access goes through the tunnel.

{{ partial "icon" "shield" }}

Revoke instantly

Revoking a daemon closes its relay at once. TLS 1.3 throughout.
